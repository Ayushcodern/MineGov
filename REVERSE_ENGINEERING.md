# CM-GIP Mobile App: Reverse Engineering & Architecture Document

This document provides a comprehensive reverse-engineered architectural overview of the **CM-GIP (CoalMine Governance Intelligence Platform) Mobile Application**. It details the structural design, navigation hierarchies, styling methodologies, and component interactions developed in this React Native (Expo) prototype.

---

## 1. Tech Stack & Fundamentals
- **Framework:** React Native (managed by Expo).
- **Routing/Navigation:** React Navigation v7 (`@react-navigation/stack`, `@react-navigation/bottom-tabs`).
- **Icons:** `@expo/vector-icons` (specifically the `Ionicons` set).
- **Styling:** Vanilla React Native `StyleSheet` paired with a central `theme.js` design system to enforce a premium, scalable aesthetic without relying on external UI libraries like Tailwind.

## 3. Navigation Architecture

The app employs a nested routing architecture managed within `AppNavigator.js`.

### A. Root Stack Navigator
The overarching navigation is a Stack Navigator that handles authentication flows and full-screen modals/wizards.
1. **`Login`**: The entry point.
2. **`PasswordChange`**: Intercepts first-time logins.
3. **`Main`**: The core application shell (hosts the Bottom Tab Navigator).
4. **`InspectionFlow`**: Pushed onto the stack to provide a full-screen, uninterrupted field reporting wizard.
5. **`ReviewFlow`**: Pushed onto the stack to provide managers a focused view of submitted reports.

### B. Main Tab Navigator
Nested within the `Main` stack screen, this provides the primary navigation for authenticated users.
- **`Dashboard`**: Overview of KPIs and quick actions.
- **`Tasks`**: Filterable list of pending and completed duties.
- **`Alerts`**: Feed of system events and compliance warnings.
- **`Profile`**: User settings and logout mechanism.

## 4. Screen-by-Screen Breakdown

### 1. `LoginScreen.js`
- **Purpose:** Entry portal.
- **Logic Engine:** Uses dummy state to intercept users. If the dummy password equals `temp123`, the app artificially routes the user to `PasswordChange`. Otherwise, it routes directly to `Main`.

### 2. `PasswordChangeScreen.js`
- **Purpose:** Enforces security policies for first-time logins.
- **UI Details:** Utilizes `KeyboardAvoidingView` to maintain layout integrity. Contains simulated validation logic ensuring the new password matches the confirmation password before allowing progression.

### 3. `DashboardScreen.js`
- **Purpose:** Central hub for user activity.
- **UI Details:** 
  - Displays dynamic KPI cards (Compliance Rate, Pending Tasks).
  - Features "Quick Actions" (Start Inspection, Review Reports) that map directly to the `InspectionFlow` and `ReviewFlow` stack routes.
  - Displays a prioritized list of "Upcoming Deadlines".

### 4. `TasksScreen.js`
- **Purpose:** To-do list management.
- **Logic Engine:** Renders a `FlatList` of tasks mapped to different severities. Clicking any task marked as 'pending' triggers the `InspectionFlow`. 

### 5. `InspectionScreen.js` (The Reporting Wizard)
- **Purpose:** Simulates an on-site field inspection.
- **Logic Engine:** Implements local state (`step`) to paginate through a 3-part wizard seamlessly:
  - **Step 1 (Location):** Simulates a verified GPS/Geofence lock.
  - **Step 2 (Checklist):** Interactive checklist utilizing array state manipulation.
  - **Step 3 (Evidence):** Simulates capturing photographic evidence and digital signatures, terminating with an `Alert.alert()` before returning to the previous screen.

### 6. `ComplianceReviewScreen.js`
- **Purpose:** Managerial portal for approving field reports.
- **UI Details:** Displays read-only data mapping to the outputs generated by `InspectionScreen.js`. Uses high-contrast UI elements to flag anomalies (e.g., Faded Signs). Features two primary terminal actions: Approve or Reject.

### 7. `AlertsScreen.js`
- **Purpose:** System notification center.
- **Logic Engine:** Utilizes helper functions (`getIconForType`, `getColorForType`) to dynamically style notifications based on severity (danger, success, warning, info) and visually distinguishes unread alerts.

### 8. `ProfileScreen.js`
- **Purpose:** User management.
- **Logic Engine:** Houses the logout mechanism (`navigation.reset`) to securely clear the navigation stack and return the user to the `Login` screen, preventing back-button exploits.

## 5. Design System (`theme.js`)

Instead of hard-coding hex values, the app strictly relies on a centralized `theme` object. This ensures visual consistency and makes future dark-mode implementations trivial.

- **Colors:** Employs a mature, accessible palette (e.g., Primary Blue `#2B6CB0`, Success Green `#48BB78`, Danger Red `#F56565`).
- **Spacing & Layout:** Standardized spacing units (`sm`, `md`, `lg`, `xl`) and border radii ensure uniform padding and modern card-based layouts.
- **Elevation:** Relies heavily on soft, simulated drop-shadows to separate interactive cards from the background canvas.
